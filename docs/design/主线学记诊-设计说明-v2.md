## 1. 范围与边界

| 范围 | 内容 |
|---|---|
| 负责 | 学：按知识点分段学习原样资料、进度与断点<br>记：作答对错、答题耗时、理由原文、非客观题判分<br>诊：个人薄弱项、班级难点、真题重点<br>AI 评测：四项图谱指标、薄弱项一致率、评测台账 |
| 上游 | E5 知识图谱（夏念航）：知识点抽取、关系、题目关联，输出待审核 |
| 下游 | 画 / 荐 / 干（晏宇涵）：展示、推荐、干预，本轮仅接口预留 |
| 不负责 | 学习资料二次加工；掌握度打分；个性化推荐算法 |

## 2. 功能设计（图1）

五个功能带：

1. **上游 E5**：资料导入 → 知识点抽取 → 归一与关系 → 题目关联 → 人工审核。
2. **学**：知识点浏览 → 原样资料学习（页码 / 时间戳定位）→ 学习进度 → 学完即练。
3. **记**：作答提交 → 客观题程序判分 / 非客观题 AI 初判 → 教师复核 → 记录（对错 / 耗时 / 理由）。
4. **诊**：按知识点聚合 → 薄弱项判定（正确率＋耗时）→ 班级难点 → 真题重点 → 报告。
5. **AI 评测**：标注集、四项图谱指标、薄弱项一致率、评测台账。

## 3. 领域模型（图2）

内容域：`KnowledgePoint`、`KPRelation`、`LearningResource`、`ResourceKP`、`Question`、`QuestionKP`、`ExamKpScore`、`KeyPoint`。

学习诊断域：`Student`、`LearningSession`、`AnswerRecord`、`WeaknessItem`、`WeaknessRule`、`DifficultyPoint`、`DiagnosisReport`、`EvaluationRun`。

关键约束：

- 知识点必须有 `source_quote`（原文出处），否则丢弃；
- 知识点与资源、题目均为多对多；
- `AnswerRecord` 是唯一证据来源，`reason_text` 只追加；
- `WeaknessItem.sufficiency = INSUFFICIENT` 是独立状态，不等于掌握差。

## 4. 数据库设计（图3、图4）

20 张表，六组：

| 组 | 表 |
|---|---|
| A 用户与内容（9） | users、courses、chapters、knowledge_points、kp_relations、learning_resources、resource_kp、questions、question_kp |
| B 考试与重点（2） | exam_papers、exam_kp_scores |
| C 学习（2） | learning_sessions、learning_progress |
| D 答题（2） | quiz_attempts、answer_records |
| E 诊断（4） | weakness_items、difficulty_points、key_points、diagnosis_reports |
| F 评测（1） | evaluation_runs |

关键字段：

- `answer_records.duration_sec`：答题耗时，第二判据；
- `answer_records.judge_type`：PROGRAM / AI / HUMAN；
- `weakness_items.time_ratio`：个人耗时 ÷ 全体正确作答平均耗时；
- `difficulty_points.weak_ratio`：薄弱人数占比，用于难点排序；
- `key_points.score_share`：真题分值得分率，用于重点排序；
- 所有阈值带 `rule_version`，默认 `v1-candidate`。

完整 DDL 见 [`db/schema_v2.sql`](db/schema_v2.sql)。

## 5. 动态设计

### 5.1 学（图5a、6a、7a）

选择知识点 → 加载原样资料与断点 → 阅读/观看 → 本段学完 → 保存进度 → 进入练习。资料只做定位与分段，不改写。会话状态：未开始 / 学习中 / 已暂停 / 已完成 / 已过期。

### 5.2 记（图5b、6b、7b）

提交作答 → 客观题程序判分，非客观题 AI 初判（给依据）→ 教师复核（可改判留痕）→ 写作答记录（题号 / 知识点 / 对错 / 耗时 / 理由）。答题尝试状态：草稿 / 已提交 / 已判分 / 待复核 / 已确认。

### 5.3 诊（图5c、6c、7c）

聚合作答 → 计算正确率与平均耗时 → 样本是否足够：

- 不足 → `INSUFFICIENT`，给补做建议，不判掌握差；
- 足够 → 判定薄弱项 → 全班汇总难点 → 扫描真题分值确定重点 → 生成报告。

薄弱项状态：证据不足 / 候选 / 已确认 / 已排除 / 已过期。

## 6. 界面设计（图8）

- **学习页**：左知识点树；中阅读器（页码 / 时间）；右进度与练习入口。
- **答题页**：题面与理由同屏；右侧计时与答题卡；提交后显示判分依据。
- **诊断页**：学生看个人薄弱项与证据；教师看班级难点与真题重点；证据不足用灰标签。

## 7. AI 评测（图9）

| 指标 | 口径 | 候选目标 |
|---|---|---|
| 知识点召回率 | AI 抽对且人工认可 ÷ 人工标注应有数 | ≥ 80% |
| 知识点准确率 | 人工认可 ÷ AI 抽出总数 | ≥ 85% |
| 关系准确率 | 抽样 50 条题目—知识点关联人工判对比例 | ≥ 80% |
| 出处可定位率 | 知识点能在原文检索到 ÷ 总数 | ≥ 95% |
| 薄弱项一致率 | 系统判定与教师标注一致 ÷ 总数 | ≥ 80% |

流程：标注集 → 运行抽取 → 逐项比对 → 计算指标 → 达标发布 / 不达标修订重跑；每次运行写入 `evaluation_runs`，保留版本与日期。

## 8. 关键决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 学只搬运原样资料，不做二次加工 | 课程资料是唯一权威来源；改写会引入争议 |
| D2 | 记同时记录对错与耗时 | 只看正确率会漏掉"做对但很慢"的薄弱点 |
| D3 | 时间只作第二判据，且需样本足够 | 题目难度与思考时间会造成误判 |
| D4 | 证据不足是独立状态 | 样本不足不能推断掌握差 |
| D5 | 难点看人数，重点看真题分值 | 难与重要是两件事，混在一起会误导复习 |
| D6 | 阈值全部标候选并带版本 | 尚未校准，不能当结论 |

## 9. 待确认问题

| 编号 | 问题 | 计划 |
|---|---|---|
| Q1 | 最少样本数 N 取多少 | 用模拟记录跑探查二校准 |
| Q2 | 超时倍数取 1.5 还是 2 | 同上，比较误判率 |
| Q3 | 真题分值表的来源与格式 | 与教师确认一份样卷 |
| Q4 | 非客观题 AI 判分的可接受误差 | 抽样人工复核，记录改判率 |
| Q5 | 图谱抽取的模型与提示词版本 | 探查一后固定，写入 evaluation_runs |
