# 智能软件工程学习平台 · 前后端接口设计

版本：V1.0 ｜ 日期：2026-11-26 ｜ 对应：《系统设计文档.md》
适用范围：学生端 / 教师端 / 管理端 Web 页面与后端 REST API

---

## 1 通用约定

### 1.1 基础信息

| 项 | 约定 |
|---|---|
| Base URL | `http://<host>:<port>/api` |
| 内容类型 | `application/json; charset=utf-8`（上传为 `multipart/form-data`） |
| 字符编码 | UTF-8 |
| 时间格式 | ISO 8601 带时区，如 `2026-11-26T10:30:00+08:00` |
| ID | 数据库自增整数；前端不解析，仅透传 |
| 分页 | `page`（默认 1）、`page_size`（默认 20，最大 100） |
| 排序 | `sort=field`、`order=asc|desc` |

### 1.2 统一响应

成功：

```json
{ "code": 0, "message": "ok", "data": { } }
```

失败（HTTP 状态码同时置为 4xx/5xx）：

```json
{ "code": 40001, "message": "缺少参数：kp_id", "details": { "field": "kp_id" } }
```

分页数据：

```json
{ "code": 0, "message": "ok", "data": { "items": [], "total": 0, "page": 1, "page_size": 20 } }
```

### 1.3 鉴权

- 登录成功后返回 JWT，前端存入 `sessionStorage`，后续请求带 `Authorization: Bearer <token>`。
- 角色由 token 中的 `role` 声明，后端按路径前缀校验：
  - `/api/student/*` → student
  - `/api/teacher/*` → teacher
  - `/api/admin/*` → admin
  - `/api/eval/*`、`/api/llm-status` → teacher 或 admin
- 演示模式（`auth.demo_mode=true`）允许仅凭账号登录，响应带 `"demo": true`，界面必须提示“演示模式，无密码校验”。

### 1.4 错误码

| 码 | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 40001 | 400 | 缺少必填参数 |
| 40002 | 400 | 参数非法（类型/范围/枚举） |
| 40101 | 401 | 未登录或 token 无效 |
| 40102 | 401 | token 过期 |
| 40301 | 403 | 无权限访问该资源 |
| 40401 | 404 | 资源不存在 |
| 40901 | 409 | 状态冲突（如重复提交、已复核） |
| 41301 | 413 | 文件过大 |
| 42201 | 422 | 业务规则不满足（如自评超出课程范围） |
| 50001 | 500 | 服务器内部错误 |
| 50201 | 502 | AI 调用失败（服务端已回退并标注引擎） |

## 3 学生端接口

### 3.1 课程与资料

| 方法 | 路径 | 请求参数 | 响应 data |
|---|---|---|---|
| GET | /api/student/courses | — | 课程树（含章节、知识点、**自评状态**） |
| GET | /api/student/knowledge-points/{kp_id} | — | 知识点详情 + 资源 + 前置关系 + 自评 |
| GET | /api/student/resources | `kp_id?`、`type?` | 资源列表（含 `file_url`、`progress_pct`） |
| GET | /api/student/resources/{resource_id} | — | 资源详情（`content` 或 `file_url`） |

课程树示例：

```json
{
  "code": 0,
  "data": [
    {
      "course_id": 1, "name": "智能软件工程", "term": "2026秋",
      "chapters": [
        {
          "chapter_id": 1, "name": "软件测试基础", "seq": 1,
          "knowledge_points": [
            {
              "kp_id": 1, "name": "边界值分析", "description": "…",
              "learning": { "total": 2, "completed": 2, "learned_all": true },
              "self_mark": { "status": "ACTIVE", "reason": "做题总错", "updated_at": "2026-11-26T10:00:00+08:00" }

          ]
        }
      ]
    }
  ]
}
```

`self_mark` 为 `null` 表示未自评；`status` 取值 `ACTIVE`（其他状态不返回）。

### 3.2 学习进度

| 方法 | 路径 | 请求 | 响应 data |
|---|---|---|---|

### 3.3 测验与作答

| 方法 | 路径 | 请求 | 响应 data |
|---|---|---|---|
| GET | /api/student/quiz/{kp_id} | — | `{questions[], learning{}}` |
| POST | /api/student/attempts | `{kp_id}` | `{attempt_id, started_at}` |
| POST | /api/student/attempts/{attempt_id}/answers | `{question_id, answer_text, reason_text, duration_sec}` | 判分结果 + 诊断摘要 |
| POST | /api/student/attempts/{attempt_id}/submit | — | `{attempt_id, score, status}` |
| GET | /api/student/attempts/{attempt_id} | — | 尝试详情（题目、作答、判分） |
| GET | /api/student/answers | `kp_id?`、`page` | 历史作答（分页） |

提交作答响应示例（主观题）：

```json
{
  "code": 0,
  "data": {
    "answer_id": 101,
    "judge_type": "AI",
    "review_status": "PENDING",
    "is_correct": null,
    "score": 29.7,
    "judge_comment": "[引擎:LLM] 要点基本答到，缺少与等价类划分的关系",
    "diagnosis": { "kp_id": 1, "status": "WEAK_ACCURACY", "accuracy": 0.5 }
  }
}
```

规则：
- `judge_type`：`PROGRAM`（客观题）/ `AI`（主观题初判）/ `HUMAN`（教师改判后）。
- 主观题初判后 `review_status = PENDING`；教师复核前不进入最终分（设计上可先按初判分展示，需标注“待复核”）。
- `duration_sec` 由前端逐题计时，整数秒，最小 1。

### 3.4 诊断

| 方法 | 路径 | 请求 | 响应 data |
|---|---|---|---|
| GET | /api/student/diagnosis | `kp_id` | 系统判定 + 自评 + 证据 |
| GET | /api/student/diagnosis/summary | `course_id?` | 全部知识点判定摘要 |

响应示例：

```json
{
  "code": 0,
  "data": {
    "kp_id": 1, "kp_name": "边界值分析",
    "system": {
      "status": "WEAK_ACCURACY",
      "accuracy": 0.571, "attempts": 7, "correct": 4,
      "time": { "my_mean": 41.8, "class_mean": 119.6, "ratio": 0.35, "samples": 5, "min_samples": 3 },
      "rule_version": "v2-candidate", "judged_at": "2026-11-26T10:05:00+08:00"
    },
    "self_mark": { "status": "ACTIVE", "reason": "做题总错", "updated_at": "2026-11-26T10:00:00+08:00" },
    "consistency": "MATCH",
    "evidence": {
      "answers": [ { "answer_id": 1, "question_title": "…", "is_correct": false, "reason_text": "…", "duration_sec": 30 } ],
      "text_annotation": { "mark": "难点", "note": "学生常混淆有效边界与无效边界" }
    }
  }
}
```

`system.status` 枚举：`MASTERED`（已掌握）/ `WEAK_ACCURACY`（薄弱·准确率）/ `WEAK_TIME`（薄弱·时间）/ `INSUFFICIENT`（证据不足）。
`consistency`：`MATCH`（系统薄弱且自评薄弱）/ `CONFLICT`（系统已掌握但自评薄弱）/ `NONE`（无自评）。

### 3.6 自主标识薄弱知识点（新增）

| 方法 | 路径 | 权限 | 请求 | 响应 data |
|---|---|---|---|---|
| POST | /api/student/self-marks | student | `{kp_id, reason?}` | 自评记录（新增或更新） |
| GET | /api/student/self-marks | student | `status?`（默认 ACTIVE） | 自评列表（含系统判定） |
| DELETE | /api/student/self-marks/{kp_id} | student | — | `{kp_id, status:"CANCELLED"}` |

POST 示例：

```json
{ "kp_id": 1, "reason": "边界值题总是做错，概念没弄清" }
```

响应：

```json
{
  "code": 0,
  "data": {
    "mark_id": 12, "kp_id": 1, "kp_name": "边界值分析",
    "reason": "边界值题总是做错，概念没弄清",
    "status": "ACTIVE",
    "created_at": "2026-11-26T10:00:00+08:00",
    "updated_at": "2026-11-26T10:00:00+08:00"
  }
}
```

GET 响应：

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "mark_id": 12, "kp_id": 1, "kp_name": "边界值分析",
        "reason": "边界值题总是做错，概念没弄清",
        "status": "ACTIVE", "updated_at": "2026-11-26T10:00:00+08:00",
        "system_status": "WEAK_ACCURACY", "consistency": "MATCH"
      }
    ]
  }
}
```

规则：
1. 同一学生对同一知识点唯一（`UNIQUE(user_id,kp_id)`）；重复 POST 为更新理由并刷新 `updated_at`。
2. 仅可对本人所在课程的知识点自评；否则 42201。
3. `reason` 最长 200 字；可空。
4. DELETE 为状态置 `CANCELLED`，不物理删除；再次 POST 复活为 `ACTIVE`。
5. 自评不参与系统判定，仅在诊断页与教师端展示。

```json
// 请求
{ "question_id": 6, "answer_text": "边界值分析测试边界附近的值…", "reason_text": "凭记忆作答", "duration_sec": 95 }
```

### 7.3 查询诊断

`GET /api/student/diagnosis?kp_id=1`，响应见 3.4。
判定顺序：证据不足 → 准确率（第一依据）→ 时间（第二依据，样本 ≥ N）→ 已掌握。

### 7.4 自主标识

- 教师汇总：`GET /api/teacher/self-marks?kp_id=1`。

`GET /api/teacher/difficulty`，响应见 4.1；`self_marks` 为新增区块。

### 7.8 画 / 荐 / 干（对齐 PPT 契约）

画：读取 DifficultyMark 五字段（只读）

```json
GET /api/student/marks/M-1001
{ "code": 0, "data": {
  "mark_id": "M-1001", "student_id": "S-A", "kp_id": 1, "kp_name": "边界值分析",
  "observation": "边界有效性混淆",
  "evidence": ["Q-101", "Q-102"],
  "uncertainty": "仅覆盖边界值分析一个知识点",
  "next_check": "完成边界值题 3",
  "status": "PENDING_REVIEW", "confidence": 0.72,
  "evidence_source": ["图谱结构", "学情数据", "文本标注"]
} }
```

证据深链：

```json
GET /api/student/marks/M-1001/evidence
{ "code": 0, "data": [
  { "question_id": "Q-101", "kp_id": 1,
    "reason_text": "输入 61 超出了 18–60，但通常宽容处理，所以是有效边界值",
    "is_correct": false }
] }
```

荐：同步请求 + 800ms 硬超时

```json
POST /api/student/recommend-requests
{ "mark_id": "M-1001", "kp_ids": [1], "limit": 3 }
// 正常
{ "code": 0, "data": { "request_id": "R-1", "state": "SERVED", "degraded": false,
  "items": [ { "item_id": "Q-3", "type": "choice", "kp_id": 1, "est_minutes": 3 } ] } }
// 超时 / 空 / 5xx（页面回退 next_check，不弹错误）
{ "code": 0, "data": { "request_id": "R-2", "state": "DEGRADED", "degraded": true, "items": [] } }
```

干：只写动作日志

```json
POST /api/student/actions
{ "mark_id": "M-1001", "action": "GO_PRACTICE", "source_page": "mark_detail" }
{ "code": 0, "data": { "log_id": "L-8" } }
```

`action ∈ RETRY_QUESTION（回原题）/ GO_PRACTICE（去练习）/ ASK_TEACHER（问老师）`；
写失败本地队列重试；日志与 next_check 分开记录。
