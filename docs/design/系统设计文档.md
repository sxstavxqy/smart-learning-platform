## 2 系统概述

### 2.1 目标

1. **E5 上游**：从课程资料抽取带出处的知识点，建立先修关系并联结题库；
2. **学**：学生按知识点学习原样资料，学完即练；可**自主标识**薄弱知识点；
3. **记**：记录答案、理由原文、作答耗时与判分类型；主观题 AI 初判、教师复核留痕；
4. **诊**：以“准确率第一依据、正确作答时间第二依据”判定个人薄弱项；
5. **画**：只读展示 E4 五字段标记与证据，支持证据深链回原题；
6. **荐**：按薄弱点推练习，同步 800ms 硬超时，失败降级到 next_check；
7. **干**：动作入口（回原题/去练习/问老师）与动作记录，只记录不干预；
8. **E4 难点发现**：结合 E5 图谱、学情与文本标注，经人机协同产出 DifficultyMark 五字段标记；
9. **重难点看板**：难题（题目级）、难点（班级）、重点（真题分值）作为统计信号与教师看板补充；
10. **AI 评测**：四指标 + 评测台账，覆盖 E5 抽取、题目关联与主观题初判；
11. **管理**：三端用户、课程、资源、题目、阈值配置、日志与备份。

### 2.2 范围

**全流程设计**：E5 → 学 → 记 → 诊 → 画 → 荐 → 干 → 重难点 → AI 评测 → 管理，全部给出页面、接口与数据设计（本文件 + 接口文档）。
**实现分阶段**：第一阶段交付 学/记/诊 + 自评 + 评测 + 管理；第二阶段按 PPT 分档交付：**画=完整**（标记列表/五字段/证据深链/状态徽标），**荐=契约+展示**（同步 800ms、失败降级 next_check），**干=只记录**（动作入口与日志，不做自动干预）；E5 的 AI 抽取与审核在教师端可用，E4 五字段标记由黄绪阳模块提供、本设计消费。
**范围外**：真实课堂部署、移动端适配、商业化运维。

### 2.3 角色

| 角色 | 职责 | 可见数据 |
|---|---|---|
| 学生 | 学习、作答、自评、查看诊断与推荐 | 仅本人数据 + 课程资料 |
| 教师 | 课程/资源管理、复核、重难点、评测、真题 | 所授课程全部学生数据 |
| 管理员 | 用户/课程/资源/题目、阈值配置、日志、备份 | 全局配置与统计（默认不看学生答案原文） |

模块归属（对齐第四组汇报 PPT）：

| 模块 | 负责人 | 说明 |
|---|---|---|
| 学 / 记 / 诊 + AI 评测 | 杨逸 | 本设计的主线范围 |
| E4 难点发现 | 黄绪阳 | 消费诊证据，输出 DifficultyMark 五字段 |
| E5 知识图谱 | 夏念航 | 图谱构建与维护，供 E4/学/诊使用 |
| 画 / 荐 / 干 | 晏宇涵 | 只读消费 DifficultyMark，动作只记录 |

### 2.4 运行形态

- Web 三端：`/student`、`/teacher`、`/admin`，门户页 `/` 选择入口；
- 前后端分离：前端静态页面（原生 ES6 + fetch，或 Vue3），后端 REST API；
- 开发环境 SQLite，生产建议 PostgreSQL 14+；
- AI 通过服务端适配层调用（Claude），密钥只存服务端环境变量。

## 3 总体设计

### 3.1 分层架构

```
表现层    学生端 / 教师端 / 管理端页面（HTML + CSS + JS）
接口层    REST API（鉴权、参数校验、统一响应、错误码）
业务层    学 / 记 / 诊 / E4 难点发现 / E5 图谱 / 画·荐·干 / AI评测 / 上传 / 管理
AI 适配层 llm_client：Claude 调用、超时、回退、引擎标注
数据层    SQLite / PostgreSQL（A-F 六组 + 自评 + 评测集 + 画荐干 7 表）
```

五层数据流见《总体流程图 V2》：数据来源（资料/题库/真题/标注集）→ 核心模块（学→记→诊）→ AI 辅助判定（E4/E5）→ 数据存储 → 展示输出（画/荐/干）。

模块契约（对齐 PPT）：诊 → E4 证据包 `EvidencePackage`；E4 → 画/荐/干 `DifficultyMark`（只读）；画 ↔ 荐 `RecommendRequest/Item`（只读+缓存，800ms 超时降级）；画 → 干 `InterventionLog`（只写）。

### 3.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS（可迁移 Vue3） | 课程演示轻量、无构建依赖 |
| 后端 | Python + Flask（或 FastAPI） | 快速交付、易读 |
| 数据库 | SQLite（开发）/ PostgreSQL（生产） | 零配置演示；生产可迁移 |
| 鉴权 | JWT（HS256）+ RBAC 中间件 | 无状态、三端共用 |
| AI | Anthropic Claude（claude-opus-5-5） | 真实调用；失败回退规则引擎 |
| 文件 | 本地 uploads/（生产建议对象存储） | 演示简单；接口不变可替换 |

### 3.3 目录结构（建议）

```
app/
  main.py               # 应用入口、路由注册
  config.py             # 阈值、路径、密钥（环境变量）
  auth.py               # 登录、JWT、角色装饰器
  db.py                 # 连接、迁移、种子数据
  modules/
    learning.py         # 学：课程、资源、进度
    answering.py        # 记：作答、判分、复核
    diagnosis.py        # 诊：薄弱项、证据包
    difficulty.py       # 难题 / 难点 / 重点
    self_marks.py       # 学生自主标识（新增）
    evaluation.py       # AI 评测
    uploads.py          # 资料上传
    admin.py            # 管理端
  llm_client.py         # AI 适配层
  static/  templates/   # 三端页面与资源
docs/                   # 设计、测试、schema
```

### 4.4 新增功能：学生自主标识薄弱知识点

#### 4.4.1 需求

| 编号 | 需求 | 验收要点 |
|---|---|---|
| REQ-SELF-01 | 学生可在课程结构页对任意知识点标记“我薄弱” | 标记成功；同知识点重复标记为更新理由 |
| REQ-SELF-02 | 学生可填写/修改自评理由（≤200 字） | 理由保存并可回显 |
| REQ-SELF-03 | 学生可取消自评 | 状态变为 CANCELLED，历史保留 |
| REQ-SELF-04 | 诊断页并列展示系统判定与自评 | 两者一致/冲突均有明确标识 |
| REQ-SELF-05 | 教师端按知识点汇总自评人数与理由样例 | 显示人数、占比、与系统判定一致率 |
| REQ-SELF-06 | 自评不改变系统判定 | 薄弱项计算不读取自评；仅作展示与推荐优先级 |

#### 4.4.2 业务规则

1. 每个学生对每个知识点最多一条 `ACTIVE` 记录；重复提交视为更新（理由、时间）。
2. 取消为状态变更（`CANCELLED`），不物理删除，保留审计。
3. 自评不参与准确率、时间比值、N 门槛等任何系统判定；诊断页以“自评（主观）”单独成栏。
4. 冲突展示：系统判“已掌握”但学生自评薄弱 → 显示“自评与系统不一致，建议复习后复测”；系统判薄弱且学生自评 → 显示“一致”。
5. 教师端汇总：按知识点统计 `ACTIVE` 人数、占比、理由样例（最多 3 条）、与系统判定一致人数。
6. 推荐（荐，下游）可将自评知识点排前，但接口返回中必须区分 `source=SELF` 与 `source=SYSTEM`。

#### 4.4.3 数据模型

```sql
CREATE TABLE self_weak_marks (
    mark_id     BIGSERIAL PRIMARY KEY,
    user_id     BIGINT NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    kp_id       BIGINT NOT NULL REFERENCES knowledge_points(kp_id) ON DELETE CASCADE,
    reason      VARCHAR(200),
    status      VARCHAR(16) NOT NULL DEFAULT 'ACTIVE'
                CHECK (status IN ('ACTIVE', 'CANCELLED')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (user_id, kp_id)
);
CREATE INDEX idx_self_marks_kp ON self_weak_marks(kp_id, status);
COMMENT ON TABLE self_weak_marks IS '学生自主标识薄弱知识点（主观证据，不参与系统判定）';
```

#### 4.4.4 接口（详见接口文档第 3.6 节）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/student/self-marks | 新增或更新自评 |
| GET | /api/student/self-marks | 查询本人自评（默认 ACTIVE） |
| DELETE | /api/student/self-marks/{kp_id} | 取消自评（置 CANCELLED） |
| GET | /api/teacher/self-marks | 教师端按知识点汇总 |

#### 4.4.5 页面交互

- **课程结构页**：每个知识点行尾按钮：未标记 →「标为薄弱」；已标记 →「已标薄弱 · 取消」。点击弹出理由输入（可空）。
- **诊断结果页**：新增“我的自评”区块：知识点、理由、时间、状态；与系统判定并排，显示一致/冲突标签。
- **教师重难点页**：新增“学生自主标识”表：知识点、自评人数、占比、理由样例、与系统判定一致数；点击行可展开学生列表。

## 5 全流程设计

本节按总体流程图 V2 的完整链路组织：**E5 知识图谱（上游）→ 学 → 记 → 诊 → 画 → 荐 → 干（下游）→ 重难点 → AI 评测 → 内容与资料管理**。每条流程都给出输入、处理、输出与落地页面/接口。

全流程链路：

```
课程资料 / 视频 / 讲义
        │
        ▼
E5 知识图谱：切块 → LLM 抽取（强制出处）→ 归一 → 人工审核 → 关系 → 题目关联
        │
        ▼
学：选择知识点 → 学习原样资料 → 进度记录 → 学完即练 → 自主标识薄弱
        │
        ▼
记：提交作答（答案 + 理由 + 耗时）→ 客观题程序判分 / 主观题 AI 初判 → 教师复核
        │
        ▼
诊：证据聚合 → 准确率（第一依据）→ 时间比值（第二依据，样本 ≥ N）→ 薄弱项 / 证据不足
        │
        ├──► 画：四态画像 + 证据回溯（回到原题）
        │
        ├──► 荐：系统薄弱 + 自评 → 练习 / 复习推荐
        │
        └──► 干：教师干预 → 学生完成 / 反馈 → 新作答回流到“记”
                                          │
重难点：难题（题目级）/ 难点（班级）/ 重点（真题） ◄── 诊 + 题库统计 + 真题分值
AI 评测：标注集 → 运行 → 四指标 → 台账 → 修订重跑（贯穿 E5 / 判分 / 诊断一致性）
```



### 5.1 E5 知识图谱构建（上游输入）

1. **资料入库**：课件 / 视频 / 讲义挂到章节（资源表 resource_kp 关联知识点）；
2. **切块**：按章节或小节切块，作为抽取单元；
3. **抽取**：LLM 从文本抽取知识点，每个知识点必须给出 `source_quote`（原文逐字片段），无出处一律丢弃（防幻觉）；
4. **归一**：同名 / 近义知识点合并，保留出处、置信度与模型/提示词版本；
5. **人工审核**：`PENDING_REVIEW → CONFIRMED / REJECTED`，审核人、时间留痕；
6. **关系构建**：`prerequisite`（先修）/ `related`（相关）/ `contains`（包含）；先修关系做环检测，禁止成环；
7. **题目关联**：题目与知识点多对多（`question_kp`），每道题指定唯一**主考点**，答题记录按主考点归集；
8. **发布**：图谱供学（学习路径）、诊（前置依赖分析）、E4（结构证据）、荐（推荐排序）使用；评测台账记录抽取质量（召回 / 准确 / 关系 / 出处可定位）；
9. **与 E4 协同**：图谱结构作为 E4 输入之一；E4 审核后的难度/重难点结论回写图谱节点属性（如 difficulty_weight、status）；题目-知识点关联（question_kp）使答题记录可按主考点聚合，供 E4 交叉验证“结构重要”与“学习困难”。

### 5.2 学

1. 学生进入课程，按章节 / 知识点选择资料；
2. 阅读课件 / 视频 / 图文，前端上报进度（幂等：同一资源只保留最大进度）；
3. 学完全部资源后进入测验；未学完给予提示（不强制）；
4. 学生可随时对知识点**自主标识薄弱**（见 4.4），自评与学习状态并列展示；
5. 学习页展示：资料列表、完成度、学完即练入口、自评状态。

### 5.3 记（判分与复核）

```
提交作答（答案 + 理由原文 + 耗时）
  ├─ 客观题 → 程序判分 PROGRAM → 记录
  └─ 主观题 → AI 初判（PENDING）→ 教师复核改判（OVERRIDDEN，留痕）→ 记录最终分
```

- 原始提交与 AI 初判不可改写；改判写 `grade_reviews`（原 AI 分、教师分、意见、时间）；
- 判分类型：`PROGRAM` / `AI` / `HUMAN`；复核状态：`NONE` / `PENDING` / `CONFIRMED` / `OVERRIDDEN`；
- 记录字段：答案、理由原文、耗时、判分类型、最终分、复核状态、主考点；
- 提交后立即触发该知识点的诊断重算（5.4）。

### 5.4 诊（个人薄弱项）

判定顺序（阈值均为候选值，存 system_config，快照带 rule_version）：

1. 无作答 → `INSUFFICIENT`（证据不足），不判掌握差；
2. 准确率 < 60% → 薄弱（准确率，第一依据）；
3. 准确率达标，正确作答样本 < N（默认 3）→ 已掌握（时间证据不足）；
4. 正确作答均时 / 班级正确作答均时 > 1.5 → 薄弱（时间，第二依据）；
5. 否则 → 已掌握。

证据包：答题数、正确数、准确率、我的正确作答均时、班级均时、时间比值、样本数、文本标注；每次判定留存快照。

**自评不参与以上任何一步**，仅在诊断页与教师端并列展示（一致 / 冲突）。

### 5.5 画（画像与证据定位）

对齐第四组汇报 PPT 的“画”设计，**只读展示**，不重算结论：

- **输入**：E4 五字段标记 `DifficultyMark`（只读）、诊 `EvidencePackage`（只读）、内容域知识点；
- **功能**：标记列表与分组（按状态 / 知识点 / 我的-班级）；五字段详情（observation、evidence、uncertainty、next_check、status）；证据深链（题号 → 原始作答，只读）；状态徽标与图例（四态四色）；**禁用词拦截**（不得出现“掌握度低 / 差 / 不认真”）；
- **两个判断**：
  1. 有没有标记？没有 → 空态 + `next_check` 补证入口，不猜、不用行为数据补；
  2. 证据能不能定位？不能 → 灰条“证据缺失，暂不下结论”，保留标记与题号，不把结论降级为推测；
- **数据**：`mark_views`（曝光幂等：mark_id + scope + filter_hash）、`review_actions`（教师确认/驳回）；
- **原则**：展示层不改标记状态；E4 的 status（PENDING_REVIEW / CONFIRMED / REJECTED / INSUFFICIENT）只读投影。

### 5.6 荐（按薄弱点推练习）

- **入口**：画像页“去练习”（markId + kpIds），请求不含个人信息；
- **调用**：同步请求 + **硬超时 800ms**；成功返回 1–3 条候选（类型 / 知识点 / 预计时长）；
- **降级**：空（EMPTY）、超时或 5xx（DEGRADED）→ `degraded=true`，回退到 `next_check` 卡片 + “暂无可用练习，先完成补证”，不出现空白列表、不弹错误；
- **记录**：采纳（ADOPTED）与忽略（DISMISSED）只记录，不反馈进模型；只有 ADOPTED 写动作日志；SERVED 不写；
- **状态机**：REQUESTED → SERVED / EMPTY / DEGRADED → ADOPTED / DISMISSED；不设“推荐中”中间态；
- **数据**：`recommend_requests`（mark_id、kp_ids[]、state）、`recommend_items`（TTL 24h）。

### 5.7 干（动作入口与记录）

- **三个动作入口**：回原题 / 去练习 / 问老师；
- **只记录**：谁、何时、从哪条标记、在哪个页面发起；`intervention_logs` 只开放 INSERT；
- **与 next_check 区分**：next_check 是系统建议，动作是学生实际行为，两者不混为一谈；
- **失败处理**：写失败进入本地队列重试，不阻塞页面；
- **本轮边界**：不做自动干预，留待学期后段。

### 5.8 E4 难点发现与重难点

对齐 PPT 的 E4 模块设计（**学记诊的判定规则不改**，E4 作为独立模块消费诊的证据）：

- **输入**：E5 知识图谱（结构）、历史学情（作业/测验得分、错题分布）、课件文本标注（重点/难点/易错）；
- **AI 处理**：区分“结构重要”与“学习困难”两类信号并交叉验证；规则（正确率、错因模式）+ AI（自然语言错因归类）；
- **人机协同**：每条候选附判定依据（图谱结构证据 + 学情数据证据 + 文本证据），教师人工审核、调整权重或否决后，才写入重难点库并回写图谱节点属性；
- **输出**：`DifficultyMark` 五字段（studentId、kpId、observation、evidence[]、uncertainty、nextCheck、status）+ 难度等级 + 置信度 + 证据来源；
- **状态**：PENDING_REVIEW → CONFIRMED / REJECTED；证据不足为一等状态（INSUFFICIENT），不得写成“掌握度低”；
- **与本设计的量化看板关系**：难题（题目级）/ 难点（班级占比）/ 重点（真题分值）作为 E4 的**统计信号与教师看板补充**，不替代五字段结论；E4 结论经教师复核后才进入画/荐/干；
- **接口**：诊 → E4 的 `EvidencePackage`；E4 → 画/荐/干的 `DifficultyMark`（只读）。

### 5.9 AI 评测

1. 维护标注集（知识点抽取集、题目-知识点关系集），固定版本；
2. 运行评测：调用 LLM 抽取 / 关联，与标注比对，计算四指标；
3. 指标：召回率 ≥ 80%、准确率 ≥ 85%、关系准确率 ≥ 80%、出处可定位率 ≥ 95%（候选）；
4. 每次运行写 `evaluation_runs`（指标、目标、样本集、模型/提示词版本、引擎、是否达标）；
5. 未达标 → 修订提示词或扩充标注集 → 同一标注集重跑，旧记录保留，可前后对比。

### 5.10 资料上传与内容管理

- **资料上传**：图片（png/jpg/gif/webp/svg）、视频（mp4/webm/ogg/mov）、文档（pdf/ppt/doc/xlsx/txt/md）；单文件 ≤ 300MB；服务端校验扩展名与 MIME，UUID 文件名；
- **学习端渲染**：图片直显、视频 `<video>`（Range）、PDF iframe、其他下载；
- **内容管理**：课程 / 章节 / 知识点 / 题目增删改查；题目关联知识点与参考答案；资源删除同步清理磁盘文件；
- **配置管理**：阈值、N、占比、评测目标入库，带 rule_version；日志、备份、CI/CD 配置。

### 6.1 表分组（基线 schema_v2 + 新增）

| F 评测（1+2） | evaluation_runs；**新增 eval_datasets、eval_items** | 台账 + 固定标注集 |

### 6.2 关键字段

| 表 | 关键字段 | 约束 |
|---|---|---|
| answer_records | answer_text, reason_text, duration_sec, judge_type, review_status, is_correct | reason 只追加；duration ≥ 0 |
| weakness_items | correct_rate, time_ratio, sufficiency, status, rule_version | sufficiency 为一等状态 |
| self_weak_marks | user_id, kp_id, reason, status | UNIQUE(user_id,kp_id)；status ACTIVE/CANCELLED |
| evaluation_runs | metric_name, value, target, sample_set, model_version, prompt_version | 每次运行一行 |
| eval_datasets/items | name, run_type；dataset_id, expected | 固定标注集，可复查 |
| difficulty_marks | mark_id, student_id, kp_id, observation, evidence, uncertainty, next_check, status, confidence | 五字段；uk(student_id,kp_id,rule_version) |
| evidence_refs | mark_id, question_id, kp_id, reason_text, is_correct | 只引用原文，不复写 |
| mark_views | mark_id, scope, filter_hash, rendered_at | 曝光幂等 uk(mark_id,scope,filter_hash) |
| review_actions | mark_id, reviewer_id, decision, comment | 教师复核；FK mark_id |
| recommend_requests / items | request_id, mark_id, kp_ids, state；item_id, type, est_minutes | 800ms 降级；items TTL 24h |
| intervention_logs | log_id, mark_id, student_id, action, source_page | 只开放 INSERT |

### 6.3 状态机

- 答题尝试：`DRAFT → SUBMITTED → GRADED / PENDING_REVIEW → CONFIRMED`（可 ARCHIVED）
- 复核：`NONE → PENDING → CONFIRMED / OVERRIDDEN`
- 薄弱项：`INSUFFICIENT | CANDIDATE | CONFIRMED | REJECTED | EXPIRED`
- 自评：`ACTIVE ⇄ CANCELLED`；取消后再次标记复用同一行（`UNIQUE(user_id,kp_id)`），置回 ACTIVE 并更新 `updated_at`，不新增记录
- 评测运行：一次运行生成多条指标记录（或一条 JSON 汇总，二选一，接口层统一）
- E4 标记：`PENDING_REVIEW → CONFIRMED / REJECTED`；`INSUFFICIENT` 为一等状态（证据不足，不等于掌握差）
- 画展示生命周期：`NEW → SEEN → ACTED / DISMISSED / EXPIRED`（只记录“看过/做过”，不改标记结论）
- 推荐请求：`REQUESTED → SERVED / EMPTY / DEGRADED → ADOPTED / DISMISSED`（无“推荐中”中间态）

### 6.4 索引与约束

- `answer_records(kp_id, answered_at)`：诊断按知识点聚合；
- `weakness_items(user_id, kp_id, generated_at DESC)`：取最新判定；
- `self_weak_marks(kp_id, status)`：教师端汇总；
- `evaluation_runs(metric_name, run_at DESC)`：版本对比；
- `difficulty_marks(student_id, kp_id, rule_version)`：唯一；`mark_views(mark_id, scope, filter_hash)`：曝光幂等；
- `review_actions(mark_id, at)`：复核历史；`intervention_logs(student_id, at)`：动作记录；
- 所有阈值/目标存 `system_config`，写 `rule_version`。

## 9 非功能设计

### 9.1 安全

- 登录使用密码哈希（bcrypt/argon2），JWT 8 小时过期；禁止仅凭账号登录（演示模式除外，需配置开关并显式标注）；
- RBAC：学生只能访问本人数据；教师限所授课程；管理员不含学生答案原文（按需脱敏）；
- 上传：扩展名 + MIME + 大小限制，UUID 文件名，禁止路径穿越；生产加病毒扫描；
- SQL 全部参数化；输出转义防 XSS；
- 审计：登录、改判、配置变更、删除、评测运行写日志。

### 9.2 性能与降级

- 看板/诊断接口 P95 < 500ms（单课程 200 人以内）；
- 推荐同步请求硬超时 800ms，超时/空/5xx 返回 `degraded=true`，页面回退 next_check，不出现空白列表；
- E4 超时（800ms）不阻塞画像页：先渲染已有标记，顶部提示“部分数据未加载”；
- 诊断按需计算 + 快照缓存；批量重算走异步任务；
- 视频用 Range 流式传输；上传限制 300MB，生产建议分片。

### 9.5 契约与展示约束

- **只读边界**：E4 的 DifficultyMark、诊的 EvidencePackage、荐的 items 在画/干层不修改、不补写、不猜测；缺就显示缺；
- **禁用词**：画展示层拦截“掌握度低 / 差 / 不认真”等表述，证据不足只显示灰色“证据不足”；
- **只写日志**：干的动作日志只开放 INSERT，失败进入本地队列重试；
- **证据可定位**：题号 / 原文 / 判定三件套缺一不可，缺任何一件显示“证据缺失”，不降级为推测。

### 9.3 可用性与降级

- LLM 不可用 → 规则回退，界面与台账标注引擎，不伪装；
- 评测运行失败 → 记录失败原因，不写“达标”；
- 数据库每日备份，恢复流程演练。

### 9.4 可配置

- 阈值、N、占比、评测目标全部入库（system_config），带版本；
- 修改阈值不追溯历史快照（快照保留旧 rule_version）。

## 12 风险与边界

| 风险 | 影响 | 应对 |

| 阈值未经真实数据校准 | 判定偏差 | 标注候选值；上线前用真实数据回归 |
| 自评被误用为判定 | 结论失真 | 自评独立表、独立展示，不进入计算 |
| LLM 输出波动 | 评测不可比 | 固定标注集与提示词版本，台账留痕 |
| 标注集过小 | 指标不可外推 | 扩充标注集后再评价 |
| 上传安全 | 恶意文件 | 类型/大小/路径校验，生产加扫描 |

**明确边界**：画/荐/干已纳入设计并给出接口，按第二阶段实现；推荐不改变诊断结论；真题扫描结果须人工确认后才进入重点统计；所有演示数据需标注“模拟”，阈值均为候选值。
